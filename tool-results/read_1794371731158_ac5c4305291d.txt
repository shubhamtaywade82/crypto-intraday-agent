    30→## Quick Start
    31→
    32→### REST API - Synchronous
    33→```python
    34→import ccxt
    35→
    36→exchange = ccxt.binance()
    37→exchange.load_markets()
    38→ticker = exchange.fetch_ticker('BTC/USDT')
    39→print(ticker)
    40→```
    41→
    42→### REST API - Asynchronous
    43→```python
    44→import asyncio
    45→import ccxt.async_support as ccxt
    46→
    47→async def main():
    48→    exchange = ccxt.binance()
    49→    await exchange.load_markets()
    50→    ticker = await exchange.fetch_ticker('BTC/USDT')
    51→    print(ticker)
    52→    await exchange.close()  # Important!
    53→
    54→asyncio.run(main())
    55→```
    56→
    57→### WebSocket API - Real-time Updates
    58→```python
    59→import asyncio
    60→import ccxt.pro as ccxtpro
    61→
    62→async def main():
    63→    exchange = ccxtpro.binance()
    64→    while True:
    65→        ticker = await exchange.watch_ticker('BTC/USDT')
    66→        print(ticker)  # Live updates!
    67→    await exchange.close()
    68→
    69→asyncio.run(main())
    70→```

    72→## REST vs WebSocket
    73→
    74→| Import | For REST | For WebSocket |
    75→|--------|----------|---------------|
    76→| **Sync** | `import ccxt` | (WebSocket requires async) |
    77→| **Async** | `import ccxt.async_support as ccxt` | `import ccxt.pro as ccxtpro` |
    78→
    79→| Feature | REST API | WebSocket API |
    80→|---------|----------|---------------|
    81→| **Use for** | One-time queries, placing orders | Real-time monitoring, live price feeds |
    82→| **Method prefix** | `fetch_*` (fetch_ticker, fetch_order_book) | `watch_*` (watch_ticker, watch_order_book) |
    83→| **Speed** | Slower (HTTP request/response) | Faster (persistent connection) |
    84→| **Rate limits** | Strict (1-2 req/sec) | More lenient (continuous stream) |
    85→| **Best for** | Trading, account management | Price monitoring, arbitrage detection |
    86→
    87→**When to use REST:**
    88→- Placing orders
    89→- Fetching account balance
    90→- One-time data queries
    91→- Order management (cancel, fetch orders)
    92→
    93→**When to use WebSocket:**
    94→- Real-time price monitoring
    95→- Live orderbook updates
    96→- Arbitrage detection
    97→- Portfolio tracking with live updates

   114→    'enableRateLimit': True

   120→import ccxt.async_support as ccxt

   123→    'apiKey': 'YOUR_API_KEY',
   124→    'secret': 'YOUR_SECRET',

   151→### Loading Markets
   152→```python
   153→# Load all available trading pairs
   154→exchange.load_markets()

   156→# Access market information
   157→btc_market = exchange.market('BTC/USDT')

   161→### Fetching Ticker
   162→```python
   163→# Single ticker
   164→ticker = exchange.fetch_ticker('BTC/USDT')
   165→print(ticker['last'])      # Last price
   166→print(ticker['bid'])       # Best bid
   167→print(ticker['ask'])       # Best ask
   168→print(ticker['volume'])    # 24h volume
   169→
   170→# Multiple tickers (if supported)
   171→tickers = exchange.fetch_tickers(['BTC/USDT', 'ETH/USDT'])

   176→# Full orderbook

   179→print(orderbook['asks'][0])  # [price, amount]

   253→## WebSocket Operations (Real-time)
   254→
   255→### Watching Ticker (Live Price Updates)
   256→```python
   257→import asyncio
   258→import ccxt.pro as ccxtpro
   259→
   260→async def main():
   261→    exchange = ccxtpro.binance()
   262→    while True:
   263→        ticker = await exchange.watch_ticker('BTC/USDT')
   264→        print(ticker['last'], ticker['timestamp'])
   265→    await exchange.close()
   266→
   267→asyncio.run(main())
   268→```
   269→
   270→### Watching Order Book (Live Depth Updates)
   271→```python
   272→async def main():
   273→    exchange = ccxtpro.binance()
   274→    while True:
   275→        orderbook = await exchange.watch_order_book('BTC/USDT')
   276→        print('Best bid:', orderbook['bids'][0])
   277→        print('Best ask:', orderbook['asks'][0])
   278→    await exchange.close()
   279→
   280→asyncio.run(main())
   281→```
   282→
   283→### Watching Trades (Live Trade Stream)
   284→```python
   285→async def main():
   286→    exchange = ccxtpro.binance()
   287→    while True:
   288→        trades = await exchange.watch_trades('BTC/USDT')
   289→        for trade in trades:
   290→            print(trade['price'], trade['amount'], trade['side'])
   291→    await exchange.close()
   292→
   293→asyncio.run(main())
   294→```
   295→
   296→### Watching Your Orders (Live Order Updates)
   297→```python
   298→async def main():
   299→    exchange = ccxtpro.binance({
   300→        'apiKey': 'YOUR_API_KEY',
   301→        'secret': 'YOUR_SECRET'
   302→    })
   303→    while True:
   304→        orders = await exchange.watch_orders('BTC/USDT')
   305→        for order in orders:
   306→            print(order['id'], order['status'], order['filled'])
   307→    await exchange.close()
   308→
   309→asyncio.run(main())
   310→```
   311→
   312→### Watching Balance (Live Balance Updates)
   313→```python
   314→async def main():
   315→    exchange = ccxtpro.binance({
   316→        'apiKey': 'YOUR_API_KEY',
   317→        'secret': 'YOUR_SECRET'
   318→    })
   319→    while True:
   320→        balance = await exchange.watch_balance()
   321→        print('BTC:', balance['BTC'])
   322→        print('USDT:', balance['USDT'])
   323→    await exchange.close()
   324→
   325→asyncio.run(main())
   326→```
   327→
   328→### Watching Multiple Symbols
   329→```python
   330→async def main():
   331→    exchange = ccxtpro.binance()
   332→    symbols = ['BTC/USDT', 'ETH/USDT', 'SOL/USDT']
   333→
   334→    while True:
   335→        # Watch all symbols concurrently
   336→        tickers = await exchange.watch_tickers(symbols)
   337→        for symbol, ticker in tickers.items():
   338→            print(symbol, ticker['last'])
   339→    await exchange.close()
   340→
   341→asyncio.run(main())
   342→```

   582→## Proxy Configuration
   583→
   584→CCXT supports HTTP, HTTPS, and SOCKS proxies for both REST and WebSocket connections.
   585→
   586→### Setting Proxy
   587→

   665→
   666→**Use `*Ws` methods when:**
   667→- You need faster order placement (lower latency)
   668→- You're already connected via WebSocket
   669→- You want to reduce REST API rate limit usage
   670→- Trading strategies require sub-100ms latency
   671→
   672→**Use REST methods when:**
   673→- You need guaranteed execution confirmation
   674→- You're making one-off requests
   675→- The exchange doesn't support the WebSocket variant
   676→- You need detailed error responses

   737→BaseError

   745→   ├─ InsufficientFunds
   746→   ├─ InvalidOrder
   747→   └─ NotSupported

   750→### Basic Error Handling
   751→```python
   752→import ccxt
   753→
   754→try:
   755→    ticker = exchange.fetch_ticker('BTC/USDT')
   756→except ccxt.NetworkError as e:
   757→    print('Network error - retry:', str(e))

   779→### Retry Logic for Network Errors
   780→```python
   781→def fetch_with_retry(max_retries=3):
   782→    for i in range(max_retries):
   783→        try:
   784→            return exchange.fetch_ticker('BTC/USDT')
   785→        except ccxt.NetworkError:
   786→            if i < max_retries - 1:
   787→                print(f'Retry {i + 1}/{max_retries}')
   788→                exchange.sleep(1000 * (i + 1))  # Exponential backoff
   789→            else:
   790→                raise

   793→## Async vs Sync
   794→
   795→### When to Use Sync
   796→- Simple scripts
   797→- Single exchange operations
   798→- Jupyter notebooks
   799→- Quick testing
   800→
   801→### When to Use Async
   802→- Multiple concurrent operations
   803→- WebSocket connections (required)
   804→- High-performance trading bots
   805→- Multiple exchange monitoring
   806→
   807→### Sync Example
   808→```python
   809→import ccxt
   810→
   811→exchange = ccxt.binance({'enableRateLimit': True})
   812→ticker = exchange.fetch_ticker('BTC/USDT')
   813→print(ticker['last'])
   814→```
   815→
   816→### Async Example
   817→```python
   818→import asyncio
   819→import ccxt.async_support as ccxt
   820→
   821→async def main():
   822→    exchange = ccxt.binance({'enableRateLimit': True})
   823→    ticker = await exchange.fetch_ticker('BTC/USDT')
   824→    print(ticker['last'])
   825→    await exchange.close()
   826→
   827→asyncio.run(main())
   828→```
   829→
   830→### Multiple Exchanges Async
   831→```python
   832→async def fetch_all():
   833→    exchanges = [
   834→        ccxt.binance({'enableRateLimit': True}),
   835→        ccxt.coinbase({'enableRateLimit': True}),
   836→        ccxt.kraken({'enableRateLimit': True})
   837→    ]
   838→
   839→    # Fetch concurrently
   840→    tasks = [ex.fetch_ticker('BTC/USDT') for ex in exchanges]
   841→    tickers = await asyncio.gather(*tasks, return_exceptions=True)
   842→
   843→    for ex, ticker in zip(exchanges, tickers):
   844→        if isinstance(ticker, Exception):
   845→            print(f'{ex.id}: ERROR - {ticker}')
   846→        else:
   847→            print(f'{ex.id}: ${ticker["last"]}')
   848→        await ex.close()
   849→
   850→asyncio.run(fetch_all())
   851→```

   874→## Common Pitfalls
   875→
   876→### Forgetting `await` in Async Mode
   877→```python
   878→# Wrong - returns coroutine, not data
   879→async def wrong():
   880→    ticker = exchange.fetch_ticker('BTC/USDT')  # Missing await!
   881→    print(ticker['last'])  # ERROR
   882→
   883→# Correct
   884→async def correct():
   885→    ticker = await exchange.fetch_ticker('BTC/USDT')
   886→    print(ticker['last'])  # Works!
   887→```
   888→
   889→### Using Sync for WebSocket
   890→```python
   891→# Wrong - WebSocket requires async
   892→import ccxt.pro as ccxtpro
   893→exchange = ccxtpro.binance()
   894→ticker = exchange.watch_ticker('BTC/USDT')  # ERROR: Need await!
   895→
   896→# Correct
   897→import asyncio
   898→import ccxt.pro as ccxtpro
   899→
   900→async def main():
   901→    exchange = ccxtpro.binance()
   902→    ticker = await exchange.watch_ticker('BTC/USDT')
   903→    await exchange.close()
   904→
   905→asyncio.run(main())
   906→```
   907→
   908→### Not Closing Async Exchange
   909→```python
   910→# Wrong - resource leak
   911→async def wrong():
   912→    exchange = ccxt.binance()
   913→    await exchange.fetch_ticker('BTC/USDT')
   914→    # Forgot to close!
   915→
   916→# Correct
   917→async def correct():
   918→    exchange = ccxt.binance()
   919→    try:
   920→        await exchange.fetch_ticker('BTC/USDT')
   921→    finally:
   922→        await exchange.close()
   923→```
   924→
   925→### Using Sync in Async Code
   926→```python
   927→# Wrong - blocks event loop
   928→async def wrong():
   929→    exchange = ccxt.binance()  # Sync import!
   930→    ticker = exchange.fetch_ticker('BTC/USDT')  # Blocking!
   931→
   932→# Correct
   933→import ccxt.async_support as ccxt
   934→
   935→async def correct():
   936→    exchange = ccxt.binance()
   937→    ticker = await exchange.fetch_ticker('BTC/USDT')
   938→    await exchange.close()
   939→```
   940→
   941→### Using REST for Real-time Monitoring
   942→```python
   943→# Wrong - wastes rate limits
   944→while True:
   945→    ticker = exchange.fetch_ticker('BTC/USDT')  # REST
   946→    print(ticker['last'])
   947→    exchange.sleep(1000)
   948→
   949→# Correct - use WebSocket
   950→import ccxt.pro as ccxtpro
   951→
   952→async def correct():
   953→    exchange = ccxtpro.binance()
   954→    while True:
   955→        ticker = await exchange.watch_ticker('BTC/USDT')  # WebSocket
   956→        print(ticker['last'])
   957→    await exchange.close()
   958→```

  1019→## Prediction Markets
  1020→
  1021→CCXT supports prediction-market exchanges (Polymarket, Kalshi, Limitless, Myriad, Hyperliquid) under a dedicated `ccxt.prediction` namespace (**async-only** in Python — `ccxt.prediction.<id>` IS the async class). They use the same unified API, but prices are quoted **0–1** (USDC per outcome share) and the tradeable unit is an **outcome** (e.g. a market's YES/NO token), not a regular market symbol.
  1022→
  1023→```python
  1024→import asyncio
  1025→import ccxt.prediction  # async-only
  1026→
  1027→async def main():
  1028→    exchange = ccxt.prediction.polymarket()
  1029→    await exchange.load_markets()
  1030→    # discover events -> markets -> outcomes
  1031→    events = await exchange.fetch_events({'query': 'Trump'})
  1032→    outcome = events[0]['markets'][0]['outcomes'][0]
  1033→    # each outcome has: outcome (handle, e.g. 'TRUMP_OUT_PRESIDENT_2027:YES'),
  1034→    # outcomeId, market, label ('YES'/'NO')
  1035→    handle = outcome['outcome']
  1036→    ticker = await exchange.fetch_ticker(handle)
  1037→    book = await exchange.fetch_order_book(handle)
  1038→    # limit buy 5 YES shares @ 0.40 USDC (price is 0..1 per share)
  1039→    order = await exchange.create_order(handle, 'limit', 'buy', 5, 0.40)
  1040→    await exchange.cancel_order(order['id'], handle)
  1041→    await exchange.close()
  1042→
  1043→asyncio.run(main())
  1044→```
  1045→
  1046→- Price/trade methods (`fetch_ticker`, `fetch_order_book`, `fetch_ohlcv`, `fetch_trades`, `create_order`, `cancel_order`, …) take an **outcome handle or outcomeId** (the `outcome` / `outcomes` parameter), not `symbol`.
  1047→- Check support with `exchange.has['prediction']`; discover markets via `fetch_events` / `fetch_event` (or `load_markets`).

  1049→## Order Router
  1050→
  1051→Two things, either usable without the other. **A client** for the CCXT order-router service — a
  1052→separate process holding live books across many venues, which answers "what is the cheapest way to
  1053→turn asset A into asset B right now?", including bridges (`SOL -> USDT -> BTC` when no `SOL/BTC`
  1054→market exists). And **an execution engine for plans you build yourself**, which needs no router
  1055→service and no API key. It is **not** an exchange: it does not subclass `Exchange`, has no unified
  1056→methods, and is constructed directly.
  1057→
  1058→```python
  1059→import os, ccxt
  1060→
  1061→router = ccxt.OrderRouter()
  1062→
  1063→# exactly one of amountIn / amountOut
  1064→route = router.fetch_route('USDT', 'BTC', {'amountIn': 1000})
  1065→print(route['effectiveRate'], route['impactBps'], route['fillRatio'])
  1066→
  1067→# execute takes the route directly: it builds the plan, loads each venue's markets and
  1068→# runs the safety check itself, refusing to place anything on a blocking violation
  1069→report = router.execute(route, {'binance': binance, 'kraken': kraken}, {
  1070→    'strategy': 'sequential',
  1071→    'usdRates': {'USDT': 1},
  1072→})
  1073→# want to see or change the plan first? the steps in between are public and PURE (no I/O):
  1074→# build_execution_plan(route, {}) then check_execution_plan_safety(plan, markets, {})
  1075→```
  1076→
  1077→`execute` defaults to `dry_run`, and **anything other than an explicit live flag forces `dry_run`
  1078→regardless of the strategy requested** — a call that looks live but forgot the flag places nothing.
  1079→
  1080→### The service, and what it costs
  1081→
  1082→`https://docs.ccxt.com/router/api`. **Every endpoint is public**: there is no API key, no signup
  1083→and no login. The service rate-limits by client IP address instead.
  1084→
  1085→The client still accepts an `apiKey` and still sends it as `x-api-key` when you pass one, so a
  1086→deployment that fronts the service with its own authentication keeps working. With no key the
  1087→header is omitted entirely rather than sent empty.
  1088→
  1089→**The full contract is published as OpenAPI 3.1 at `https://docs.ccxt.com/router/openapi.yaml`.**
  1090→`curl -O https://docs.ccxt.com/router/openapi.yaml` and point codegen at it, import it into
  1091→Postman/Insomnia, or diff it between deploys. It is the authority on every field this client
  1092→reads; where the two disagree, the spec is right. Rendered prose version:
  1093→[/router/docs](https://docs.ccxt.com/router/docs) and
  1094→[/router/docs/api](https://docs.ccxt.com/router/docs/api).
  1095→
  1096→**Free to use for now, up to the published rate limit** — not a permanent commitment, so expect a
  1097→paid tier eventually. Your existing key is how that would be billed; nothing in the client changes.
  1098→Read the limit off the response headers (`x-ratelimit-limit`, `x-ratelimit-remaining`,
  1099→`x-ratelimit-reset`) rather than hardcoding a number. A `429` raises `RateLimitExceeded` with the
  1100→retry interval folded into the message.
  1101→
  1102→A router that has restarted is alive long before it can price anything. Asked to route in that
  1103→window it refuses with `503 cache_cold`, and the client raises **`ExchangeNotAvailable`** — a
  1104→retry, distinct from the `ExchangeError` that means something is actually wrong.
  1105→
  1106→**Holdings are POSTed, never put in a URL.** `fetch_route` normally sends a `GET`, but when you pass
  1107→`balances` the client switches to `POST /route` and puts every parameter in the body: the service
  1108→scrubs holdings from its own logs, but a reverse proxy, an ALB, a CDN, browser history and a
  1109→`Referer` all see the full request line, and no in-process redaction reaches them.
  1110→`fetch_route_with_balances` does this for you.
  1111→
  1112→
  1113→**Two flags the client verifies for you**, because one silently lost in transit looks identical to
  1114→one never sent. `balances`: the service ignores them entirely if it predates the feature and
  1115→answers byte-identically, so `fetch_route` throws unless the router echoes `balancesApplied` (or
  1116→`balanceEntryCount`, which is how an *empty* wallet is confirmed) — pass `requireBalancesApplied:
  1117→false` to opt out. `requireFullFill`: the one flag that fails *open*, so the client stamps what you
  1118→asked for and the safety check makes `partial_fill` **blocking** when you asked for a full fill and
  1119→did not get one.
  1120→
  1121→**An empty value is not an omitted one.** Omit `bridges` and you get the default bridge set; send
  1122→`bridges=` and you have asked for no bridging at all. Same for `exchanges=` (no venues) and
  1123→`balances=` (you hold nothing). The client forwards an empty value rather than dropping it.
  1124→
  1125→**`requestId`** is sent as the `x-request-id` header, so your log and the router's decision log can
  1126→be joined; the service mints one when absent.
  1127→
  1128→### Asking the service about itself
  1129→
  1130→| Method | Endpoint | Key? | Answers |
  1131→|---|---|---|---|
  1132→| `fetch_health()` | `/health` | no | is the process alive — `200` from the first millisecond of boot |
  1133→| `fetch_readiness()` | `/ready` | no | can it route yet: book counts, and how many are fresh |
  1134→| `fetch_version()` | `/version` | yes | which commit is deployed |
  1135→| `fetch_symbols()` | `/symbols` | yes | the symbols it holds a book for |
  1136→| `fetch_exchanges_status()` | `/exchanges/status` | yes | per-venue connection health |
  1137→| `fetch_cached_order_book(exchange_id, symbol)` | `/orderbook/{exchange}/{symbol}` | yes | the exact book a route was ranked on |
  1138→
  1139→Gate deploys on readiness, not health — `/health` is `200` before a single websocket has connected.
  1140→`fetch_readiness()` does **not** raise when the answer is no: the service replies `503` carrying the same
  1141→body it returns on `200`, and you need those counts to know why.
  1142→
  1143→```python
  1144→readiness = router.fetch_readiness()
  1145→if readiness['status'] != 'ready':
  1146→    print(readiness['freshCount'], 'of', readiness['bookCount'], 'books are fresh')
  1147→```
  1148→
  1149→`/metrics` (Prometheus) has no client method — it answers `text/plain` and this class parses every
  1150→response as JSON.
  1151→
  1152→**Watching a route.** `/stream/route` pushes the same RouteResult whenever any market the route
  1153→depends on moves. `watch_route` raises **`NotSupported`** in Python: this port is synchronous and has no
  1154→websocket client to drive, and polling `fetch_route` on a timer is not the same thing, so it is refused
  1155→rather than silently substituted. `streamUrl` IS implemented, so the url grammar and the
  1156→client-side refusals stay verified here. The endpoint refuses `balances` and `balanceMode` — a
  1157→socket outlives the holdings it was opened with — and defaults `includeQuotes` to false.
  1158→
  1159→### Watching a run, and stopping it
  1160→
  1161→`execute` is not opaque. `options.onStep` is called after each step completes AND after its
  1162→reconciliation — never mid-order — and its return value decides whether the route continues.
  1163→
  1164→```python
  1165→def on_step(event):
  1166→    print(event['stepIndex'], event['status'], event['outAmount'])
  1167→    return 'halt' if event['status'] == 'partial' else ''   # 'halt' stops the route
  1168→
  1169→report = router.execute(plan, venues, {
  1170→    'strategy': 'sequential', 'live': True, 'usdRates': {'USDT': 1},
  1171→    'retryFailedSteps': 2,               # only a DEFINITIVELY REJECTED step is retried
  1172→    'onStep': on_step,
  1173→})
  1174→```
  1175→
  1176→The event is a plain dictionary: `planId`, `stepIndex`, `hopIndex`, `legIndex`, `exchangeId`,
  1177→`symbol`, `side`, `status`, `requestedAmount`, `filledAmount`, `outAsset`, `outAmount`, `orderId`,
  1178→`clientOrderId`, `errorCode`, `attempt`, `reconciliation`, `ordersPlaced`, `halted`, `haltReason`,
  1179→`stepsTotal`, `stepsRemaining`.
  1180→
  1181→- **It can only narrow.** `'halt'` stops the route and sets `haltReason` to `halted_by_on_step`;
  1182→  nothing it returns resumes a route the reconciliation already halted.
  1183→- It is called on the halt paths too, with an empty `reconciliation`, so it always learns how the
  1184→  route ended.
  1185→- **Do no network I/O in it** — it sits between orders on the money path.
  1186→- A hook that throws is recorded in `report['errors']` as `on_step_hook_failed` and the run
  1187→  continues; losing the report would destroy the only account of orders already live.
  1188→
  1189→For decisions that need I/O, slice the plan and call `execute` per hop with its own
  1190→`idempotencyKey` instead.
  1191→
  1192→`options.retryFailedSteps` (default 0, `retryDelayMs` default 1000) re-places a step the venue
  1193→**definitively rejected**. An `outcome_unknown` step is never retried at any setting: it may
  1194→already be a live position, and re-placing it is the double-fill this class exists to prevent. The
  1195→winning attempt is reported as `attempt`. The router sets no client order id of its own — venues
  1196→disagree on length and charset, so whatever you pass in `orderParams` travels untouched.
  1197→
  1198→### Executing your own plans
  1199→
  1200→`execute` takes a **plan**, not a route, and never checks where the plan came from — so your own
  1201→strategy can supply its own trades and still get the notional cap, halt-and-reconcile between hops,
  1202→resting-order cleanup and the unwind plan. A plan that has been through JSON or a database, or a
  1203→hand-rebuilt tail of a halted route, is equally valid.
  1204→
  1205→A step is one order on one venue. Required: `exchangeId`, `symbol`, `side`, `amount`, `base`,
  1206→`quote`. Optional: `stepIndex` (defaults to position), `hopIndex`/`legIndex` (steps sharing a
  1207→`hopIndex` are one hop — what `parallel_within_hop` parallelises), `expectedPrice`, `limitPrice`,
  1208→`notionalQuote`.
  1209→
  1210→```python
  1211→plan = {
  1212→    'requestId': 'my-strategy-0001',            # identity; a live run refuses without one
  1213→    'calculatedAt': exchange.milliseconds(),
  1214→    'steps': [
  1215→        {'exchangeId': 'binance', 'symbol': 'BTC/USDT', 'side': 'buy', 'amount': 0.01,
  1216→         'base': 'BTC', 'quote': 'USDT', 'hopIndex': 0, 'expectedPrice': 64000},
  1217→    ],
  1218→}
  1219→report = router.execute(plan, {'binance': binance}, {
  1220→    'strategy': 'sequential', 'live': True, 'usdRates': {'USDT': 1}, 'maxNotionalUsd': 25,
  1221→})
  1222→```
  1223→
  1224→A live `execute` requires an identity and refuses without one: the identity is remembered in-process
  1225→so a second `execute` of the same plan is refused before any venue is contacted. Supply it as the
  1226→plan's `requestId` or as the options' `idempotencyKey`. `execute` never sets a `clientOrderId` of its
  1227→own: each exchange's `create_order` keeps sending whatever identifier it generates internally, and a
  1228→`clientOrderId` you put in the options' `orderParams` travels untouched (to every step alike).
  1229→
  1230→Make it stable and tied to the intent (a strategy name plus the signal's timestamp). A fresh value
  1231→per call — a wall-clock timestamp and friends — turns the guard off while looking like it is on. To
  1232→re-run deliberately, pass `allowReexecution`. The guard does not survive a restart.
  1233→
  1234→`checkExecutionPlanSafety` is worth running on a hand-written plan first: it checks every step
  1235→against that venue's real market rules — minimum amount, minimum cost, precision — which is where a
  1236→hand-picked amount usually goes wrong.
  1237→
  1238→
  1239→Strategies: `dry_run` (default), `sequential`, `parallel_within_hop` (concurrent across venues,
  1240→serialised within a venue), `limit_protected` (rests a limit order and cancels it at
  1241→`orderTimeoutMs`, polling every `pollIntervalMs`), `atomic_ish` (requires the route pre-funded),
  1242→`best_effort` (single-hop, never halts).
  1243→
  1244→Every report carries `planAgeMs` — how old the plan's prices were when `execute` was called (`-1`
  1245→when the route carried no `calculatedAt`, which means unknown, not fresh). Pass
  1246→`options.maxPlanAgeMs` to refuse a live execution of a plan older than that; there is no default
  1247→limit, and under an active limit a plan whose age cannot be determined is refused too.
  1248→
  1249→There is **no notional cap by default** — trade cents or trade thousands. `maxNotionalUsd` is an
  1250→opt-in guardrail: pass it to the constructor, or per call in the options, and it is honoured
  1251→exactly at whatever value you choose, in either direction; omit it (or pass 0) and no notional
  1252→check runs. Only a negative value is refused.
  1253→
  1254→A market order cannot be placed under a cap: the cap is checked against the plan's limit price and
  1255→a market order carries no price at all, so asking for `allowMarketOrders` together with a cap is
  1256→refused rather than silently unbounded.
  1257→
  1258→When a cap IS set it is enforced immediately before **every** order — not just at plan time,
  1259→because a reconciliation may have resized the plan since — and a step that cannot be valued in USD
  1260→**blocks**, so supply a USD rate for every quote asset in the plan. With no cap set there is
  1261→nothing to evaluate and USD rates are not required either.
  1262→
  1263→In the report, `status: 'outcome_unknown'` means the request may or may not have reached the venue
  1264→— execution halts rather than reconciling, because reconciling would read the fill as 0 and report
  1265→"nothing filled", asserting the one thing nobody knows. Check the open orders and the venue before
  1266→retrying. `placementAttempted` is false until an order was actually dispatched.
  1267→
  1268→`buildExecutionPlan` refuses a route that does not run from the asset you offered to the asset you
  1269→wanted, or whose hops do not connect — the answer is checked against the client's own record of
  1270→the question, so a compromised or buggy router response cannot steer orders into another market.
  1271→

  1274→## Bitget Stock Routing
  1275→
  1276→Default discovery cross-references classic spot symbols against public UTA spot instruments to identify stocks; loading UTA markets is not required. `symbolType: 'stock'` sets the unified market's `stock` flag; `isReality: 'yes'` is a fallback only when `symbolType` is absent. Stock-underlying derivatives retain their derivative type and do not use Reality spot REST endpoints. Stock spot WebSocket subscriptions automatically use UTA; derivatives retain classic derivative WebSockets unless `uta: true` is selected explicitly. Symbol-required methods infer stock routing from market metadata and discard legacy `params.stock` overrides. The stock selector remains available for symbol-less discovery, tickers and balances. This does not add Stock+ securities-account support or imply share ownership.
